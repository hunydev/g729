**Goal:** Implement the `internal/lsp` package — decoder-side LSP reconstruction from the 18 transmitted LSP bits (L0 1 bit + L1 7 bits + L2 5 bits + L3 5 bits). Decoder surface is one method `Decode(indices Indices) (sf1LP, sf2LP [11]int16)` plus `Reset`. ## Context for the implementing engineer

### What this package exists for

Line Spectral Pairs (LSP, also called Line Spectral Frequencies / LSF in the angular-frequency domain) are an alternative representation of the 10-order LP filter. They have two properties the quantizer exploits:

1. Perturbations in the LSP domain cause only local distortions in the LP spectral envelope, so quantizer noise is less audible than quantizing LP coefficients directly.
2. LSPs are ordered and bounded: `0 < ω_1 < ω_2 < ... < ω_10 < π`. That ordering is a sufficient condition for the LP filter's stability, which is easy to enforce after quantization.

On the decoder side, our job is:

- Receive L0, L1, L2, L3 from the bitstream (already unpacked in `internal/bitstream`).
- Combine L1, L2, L3 into a 10-element quantized *residual* `r̂(n)` via split-vector VQ.
- Apply the order-4 MA predictor selected by L0 (2 predictor sets) to turn `r̂(n)` into the quantized LSF vector `l̂(n)`.
- Enforce stability (monotonic order + minimum gap) on `l̂(n)`.
- Convert LSF → LSP via `q_i = cos(ω_i)` using the ITU cosine LUT.
- Linearly interpolate LSPs between the previous frame and the current frame so subframe 1 uses a half-weighted interpolation and subframe 2 uses the current frame directly.
- Convert each subframe's LSP vector to LP coefficients `a[0..10]` via the standard Chebyshev polynomial expansion.

Phase 1e ("synth") will consume the two `[11]int16` LP coefficient vectors this phase produces.

### Numerical conventions

The G.729 spec expresses LSF values in radians. In fixed-point, both the tables and the runtime values use **Q13 Word16**:

- The full scale `π ≈ 3.14159` maps to `round(π · 2^13) = round(25735.93) = 25736`, which fits in Word16 (Max16 = 32767).
- Adjacent LSF spacing floor from the stability rule — quoted in the spec at `J ≈ 0.0012 rad` — is `round(0.0012 · 2^13) = 10` in Q13.

MA predictor coefficients are unit-less scalars with magnitudes less than 1 and use **Q15 Word16**. LSP values (cos of an LSF) lie in `(-1, +1)` and use **Q15 Word16**. LP coefficients produced by Chebyshev expansion fit in **Q12 Word16** (leading `a[0] = 1.0` is `4096`, others bounded by LPC stability).

**Verify these Q-format choices against the spec.** If §3.2.4 states a different Q-format for any table, trust the spec over this plan and update the Q-format constants in Task 2. The plan's Q-formats are derived from the ranges above, not quoted verbatim from the spec.

### Dependency contract

- `internal/lsp` imports `internal/fixed` and `internal/tables` only.
- Every arithmetic step routes through `internal/fixed`. Go's built-in `+`, `-`, `*` on `int16` / `int32` is forbidden in codec paths (they wrap on overflow). The same rule stated in Phase 0c applies unchanged.
- No allocation in `Decoder.Decode`. State is part of the `Decoder` value, output LP vectors are returned by value (not via a slice), indices are passed by value.

### Indices type

The input to `Decode` is the unpacked indices. Keep them grouped in a tiny value type:

```go
// Indices are the bit-field indices delivered per frame by the bitstream
// unpacker, covering the LSP parameters defined in ITU-T G.729 §4 Table 9.
// All fields are the raw integer indices, not bit-field slices.
type Indices struct {
    L0 uint8 // 1 bit: MA predictor selector (0 or 1)
    L1 uint8 // 7 bits: first-stage VQ index (0..127)
    L2 uint8 // 5 bits: second-stage lower-split index (0..31)
    L3 uint8 // 5 bits: second-stage upper-split index (0..31)
}
```

The bitstream package produces a larger bag of indices (pitch, ACELP, gain, etc.); `lsp.Indices` is a *subset*. In Phase 1g the top-level decoder will construct an `lsp.Indices` value from the bitstream output, but for now `lsp.Decoder` takes the `Indices` value directly — no dependency on `bitstream`.

### Verification strategy

The Phase 1a unit tests **cannot** be bit-exact against the ITU test vectors yet. The ITU `LSP.*` test vector contains only the final LP coefficients per subframe and depends on a complete bitstream parse. Reading and consuming those vectors is Phase 1g's integration-test job.

Within Phase 1a the verification is property-based:

- **Table shape & range:** dimensions match the spec's row/column counts; values fit in the documented Q-format without saturation.
- **Codebook reachability:** decoding the all-zero indices `{L0:0, L1:0, L2:0, L3:0}` against a freshly-Reset decoder produces a stable LSF vector (monotonic, all values in `(0, π)` after stability), and produces DIFFERENT output when L0 is flipped to 1 (proving the predictor selector is wired).
- **Stability enforcement:** feed a hand-constructed unstable LSF (out of order, too close) through `stability.Enforce` and check the output is strictly monotonic with gaps ≥ `Jmin`.
- **LSF ↔ LSP round-trip:** `LSF→LSP→acos` recovers the original LSF to within the cosine LUT's documented precision (≤ 1 LSB for LSF values that land exactly on grid points, ≤ 4 LSB in general).
- **Chebyshev symmetry:** F1(z) is symmetric in its coefficients, F2(z) is antisymmetric. A(z) built from F1 and F2 produces `a[0] = 1.0` exactly (Q12 value `4096`).
- **LSP→LP round-trip:** converting LP→LSP→LP (using a reference LP vector derived from a known stable all-pole resonator) recovers the LP coefficients within a documented tolerance. The LP→LSP direction is part of the LPC analysis, not this phase, so for this round-trip the test constructs a known LSP vector, converts to LP, then converts LP→LSP by computing the roots of A(z) with a brute-force grid search (test-only helper, not shipped in the package).
- **Zero allocation:** `Decoder.Decode` runs with `testing.AllocsPerRun` = 0.

### Frame cadence

Decoder state is advanced exactly once per frame (not per subframe). The LSP history used for interpolation holds **one** past frame's LSP vector. After calling `Decode`, the current frame's LSP becomes the "past" for the next frame.

```go
                t.Errorf("LSPCodebookL1[%d][%d] = %d out of sane range ±%d",
                    i, j, v, cap)
            }
        }
    }
```

Reconstruct the quantized LSF `l̂(n)` from the residual `r̂(n)` and the past 4 residuals via the MA predictor. The ITU equation is in §3.2.4 (also repeated in §4.1.1); read it there and match it exactly. The general shape, which your implementation must match:

```
l̂(n)[i] = (1 − Σ_{k=1..4} p_k^{L0}[i]) · r̂(n)[i] + Σ_{k=1..4} p_k^{L0}[i] · r̂(n−k)[i]
```

where `p_k^{L0}[i]` is the Q15 coefficient `MAPredictorsLSP[L0][k-1][i]`. The complementary coefficient `(1 − Σ_k p_k[i])` is computed at runtime per LSF dimension (it is *not* a table lookup).

**Q-format analysis for the accumulator path:**

- `p_k` is Q15 Word16.
- `r̂` is Q13 Word16.
- `fixed.LMult(p_k, r̂)` produces Q(15+13+1) = Q29 Word32 — too high a Q for later steps.
- Approach: use `fixed.LMac` with a Q14 scaling. Specifically, since `(1 − Σp)` can be negative in extreme predictor configurations and its magnitude can exceed 1, keep the final output in Q13 by dividing the Q29 accumulator by 2^16 — i.e. `fixed.Round(acc)` gives Q(29-16) = Q13.
- Alternatively, compute the per-dimension sum in a 32-bit accumulator with `LMac` (each `LMac` contributes Q29 terms; 5 `LMac`s sum in Q29), then `fixed.Round` to Q13.

**There is a subtler option** that some implementations use: split the predictor equation so that `(1 − Σp_k) · r̂(n)` is computed first (producing Q29) and the 4 past-residual terms are added in the same accumulator. Your implementation may pick either variant as long as:

1. Every multiply goes through `fixed.LMult` / `fixed.LMac`.
2. The final result is Q13 Word16.
3. The self-consistency test in Step 1 passes.

```go
package lsp

import (
    "github.com/exedev/g729/internal/fixed"
    "github.com/exedev/g729/internal/tables"
)

// applyPredictor reconstructs the quantized LSF vector from the
// current residual r̂ and the decoder's past-residual state, per the
// order-4 MA predictor equation in ITU-T G.729 §3.2.4 / §4.1.1:
//
//   l̂(n)[i] = (1 − Σ_k p_k^{L0}[i]) · r̂(n)[i]
//           + Σ_k p_k^{L0}[i] · r̂(n-k)[i]
//
// selector picks one of the two 4-tap predictor sets. After producing
// out, applyPredictor shifts the past-residual FIFO and installs r̂ as
// the new r̂(n-1).
//
// Q-format contract:
//   residual: Q13 Word16
//   predictor coefficients: Q15 Word16
//   out: Q13 Word16
//
// The intermediate products are Q29 Word32; a single fixed.Round at
// the end brings the accumulated sum back to Q13.
func (d *Decoder) applyPredictor(selector uint8, residual, out *[10]int16) {
    preds := &tables.MAPredictorsLSP[selector]

    for i := 0; i < 10; i++ {
        // Build Σ_k p_k[i] in Q15 Word16 with saturation.
        var sumP int16
        for k := 0; k < 4; k++ {
            sumP = fixed.Add(sumP, preds[k][i])
        }
        // Complementary coefficient: (1 − Σp) in Q15. Max16 = 32767
        // represents just under 1.0; treating it as 1.0 here is the
        // spec's intended convention.
        comp := fixed.Sub(fixed.Max16, sumP)

        // acc = comp · r̂(n)[i] + Σ_k p_k[i] · r̂(n-k)[i], all terms
        // Q29 = Q15 · Q13 · 2 via LMac.
        var acc fixed.Word32
        acc = fixed.LMac(acc, comp, residual[i])
        acc = fixed.LMac(acc, preds[0][i], d.pastResiduals[0][i])
        acc = fixed.LMac(acc, preds[1][i], d.pastResiduals[1][i])
        acc = fixed.LMac(acc, preds[2][i], d.pastResiduals[2][i])
        acc = fixed.LMac(acc, preds[3][i], d.pastResiduals[3][i])

        // Q29 → Q13 by rounding right shift of 16 bits (fixed.Round).
        out[i] = fixed.Round(acc)
    }

    // Shift past-residual FIFO: r̂(n-3) → r̂(n-4), ..., r̂(n) → r̂(n-1).
    d.pastResiduals[3] = d.pastResiduals[2]
    d.pastResiduals[2] = d.pastResiduals[1]
    d.pastResiduals[1] = d.pastResiduals[0]
    d.pastResiduals[0] = *residual
}
```

**Double-check the equation against the spec before you commit this task.** If the spec writes the predictor with `r̂(n)` *added* to the predicted value rather than with the `(1 − Σp)` factor — i.e. `l̂(n) = r̂(n) + Σ_k p_k · r̂(n-k)` — use *that* formulation instead and delete the `comp` computation. The predictor test checks behavioural properties (selector matters, state advances, impulse response is positive and smaller than impulse) that hold for either formulation, so tests alone cannot pick between them; the spec does.

Per ITU-T G.729 §3.2.4 / §4.1.1 the decoder enforces two stability rules on the reconstructed LSF vector:

1. Monotonic order: `l̂[0] < l̂[1] < ... < l̂[9]`.
2. Minimum adjacent distance: `l̂[i+1] − l̂[i] ≥ J` where J ≈ 0.0012 rad (Q13 value 10).

(Verify the exact Q13 minimum-gap constant against §3.2.4 / §4.1.1. The ITU reference value 0.0012 is quoted widely, but the spec is the authority.)

```
for i = 0 .. 9:
    if l̂[i] < J/2:                    // also clamp to a small positive value
        l̂[i] = J/2
    if i > 0 and l̂[i] − l̂[i-1] < J:
        l̂[i] = l̂[i-1] + J
```

Also clamp `l̂[9]` against an upper bound `π − J/2` (Q13 value `25736 − 5 = 25731`).

```go
package lsp

import "github.com/exedev/g729/internal/fixed"

// Stability thresholds per ITU-T G.729 §3.2.4 / §4.1.1. Verify these
// constants against the spec before shipping — the values here are
// from the widely-cited formulation (J ≈ 0.0012 rad) and the plan
// trusts that. π ≈ 25736 in Q13.
const (
    lsfMinGap  = 10    // Q13 approximation of J ≈ 0.0012 rad
    lsfMinEdge = 5     // Q13 approximation of J/2 ≈ 0.0006 rad
    lsfMaxEdge = 25731 // Q13 approximation of π − J/2
)

// enforceLSFStability makes lsf strictly monotone and respecting the
// minimum adjacent gap, in-place. It is a single forward pass with a
// bounded-edge clamp — O(10) and zero-alloc.
func enforceLSFStability(lsf *[10]int16) {
    if lsf[0] < lsfMinEdge {
        lsf[0] = lsfMinEdge
    }
    for i := 1; i < 10; i++ {
        // If lsf[i] crowds lsf[i-1], push it up.
        minNext := fixed.Add(lsf[i-1], lsfMinGap)
        if lsf[i] < minNext {
            lsf[i] = minNext
        }
    }
    if lsf[9] > lsfMaxEdge {
        lsf[9] = lsfMaxEdge
        // Back-propagate the ceiling.
        for i := 9; i > 0; i-- {
            maxPrev := fixed.Sub(lsf[i], lsfMinGap)
            if lsf[i-1] > maxPrev {
                lsf[i-1] = maxPrev
            }
        }
    }
}
```

- [ ] **Step 3: Implement `lsfToLSP`**

Create `internal/lsp/lsf_lsp.go`. The algorithm is: (a) fold ω into `[0, π/2]` by reflection, (b) compute an LUT index and fractional remainder from ω's position within that fold, (c) linearly interpolate between `CosLSP[idx]` and `CosLSP[idx+1]`, (d) negate the result if the fold happened. Derivation of the integer arithmetic is given in §3.2.5 of the spec but the shift counts here are derived directly from the Q-format rather than quoted:

- `halfPi = round(π/2 · 2^13) = 12868`. Any ω in `[0, halfPi]` is already first-quadrant; any `ω > halfPi` is folded to `2·halfPi − ω` with the output negated.
- After folding, the folded value `w` spans `[0, halfPi]`. Divide this range into 64 uniform intervals so the interpolation uses 65 LUT endpoints (`CosLSP[0..64]`).
- With `w ∈ [0, 12868]` spanning 64 intervals, each interval is `12868 / 64 = 201.06…` Q13 units wide — not a power of 2. The clean way to compute index+fraction without integer division is `(w * 64) / 12868`, but that requires a 32-bit divide. The preferred fixed-point scheme is: pre-scale `w` to a Q-format where the divide collapses into a shift. Multiplying `w` by `65536 / 12868 ≈ 5.0929` (Q15 constant `round(5.0929 · 2^15) = 166846`... too big for Q15) — no, this won't give a clean shift either.
- The practical workaround ITU uses: **extend the LUT to 65 entries covering `[0, π/2]` using a power-of-2 grid spacing** — the LUT-step convention in §3.2.5 matches an ω scale where the high bits of `w` index the LUT directly. **Read §3.2.5 and match the spec's exact convention.** The plan's Q-format derivation above is correct about π/2 being 12868 in Q13; the spec's LUT grid may use a slightly different full-scale (e.g. `w` scaled so that `π/2 = 2^13`, not `12868`, which is a different internal convention).

Given the ambiguity, implement in two passes:

**Pass 1 — matches the plan's Q13 convention exactly, verified by Step 1 tests:**

```go
package lsp

import (
    "github.com/exedev/g729/internal/fixed"
    "github.com/exedev/g729/internal/tables"
)

const (
    // halfPi is π/2 in Q13. Matches tables.CosLSP coverage of [0, π/2].
    halfPi int16 = 12868
)

// lsfToLSP converts one LSF value ω (Q13, 0 ≤ ω < π) to its LSP
// value cos(ω) (Q15) via tables.CosLSP + linear interpolation, per
// ITU-T G.729 §3.2.5.
//
// The LUT covers [0, π/2] in 64 equal intervals (65 endpoints). For
// ω > π/2, use cos(ω) = −cos(π − ω) by reflecting the query and
// negating the result.
func lsfToLSP(omega int16) int16 {
    neg := false
    w := omega
    if w > halfPi {
        w = fixed.Sub(fixed.Add(halfPi, halfPi), w)
        neg = true
    }
    if w < 0 {
        w = 0
    }
    if w > halfPi {
        w = halfPi
    }

    // Position w within [0, halfPi] as a fraction in Q-step, split
    // into integer LUT index (0..63) and fractional remainder (0..step−1).
    // With halfPi = 12868 divided into 64 intervals, each interval is
    // 201 Q13 units wide (with a sub-unit error absorbed into the
    // interpolator's tolerance).
    const step = 201 // floor(halfPi / 64)

    idx := int(w) / step
    if idx >= 64 {
        idx = 63
    }
    frac := int32(w) - int32(idx)*int32(step)

    // Linear interpolation: cos(w) ≈ c0 + frac·(c1 − c0)/step.
    c0 := int32(tables.CosLSP[idx])
    c1 := int32(tables.CosLSP[idx+1])
    interp := c0 + ((c1-c0)*frac)/int32(step)

    if neg {
        interp = -interp
    }
    // Saturate into Word16 range (guards against fold edges).
    if interp > 32767 {
        interp = 32767
    } else if interp < -32768 {
        interp = -32768
    }
    return int16(interp)
}
```

If the spec uses a different internal Q-format for ω (e.g. Q14 with π = 2^14, a convention where `step = 2^n` and index/fraction extraction is a shift instead of a divide), rewrite the index/fraction/interp lines to match. The Step 1 tests will still pass under either convention because they only check boundary values and monotonicity. Document the final convention in the completion report.

If the spec uses a shift-friendly `step = 2^k`, both `/step` occurrences collapse into `>> k` and the implementation is strictly faster — prefer that form when it's what the spec says.

Per ITU-T G.729 §4.1.2, the subframe-wise LP filters are derived from interpolated LSP vectors:

- Subframe 1 uses `q_sf1[i] = 0.5 · q̂(n−1)[i] + 0.5 · q̂(n)[i]`.

```go
package lsp

import "github.com/exedev/g729/internal/fixed"

// interpolateLSP produces the per-subframe LSP vectors for one frame.
// Per ITU-T G.729 §4.1.2:
//
//   sf1[i] = (prev[i] + curr[i]) / 2
//   sf2[i] = curr[i]
//
// All values are Q15 Word16. The mean computation uses fixed.Add +
// fixed.Shr so that the worst-case sum saturates on Word16 instead
// of wrapping.
func interpolateLSP(prev, curr, sf1, sf2 *[10]int16) {
    for i := 0; i < 10; i++ {
        sf1[i] = fixed.Shr(fixed.Add(prev[i], curr[i]), 1)
        sf2[i] = curr[i]
    }
}
```

## Task 12: LSP → LP via Chebyshev polynomial expansion

**Files:**
- Create: `internal/lsp/lsp_lp.go`
- Create: `internal/lsp/lsp_lp_test.go`

Per ITU-T G.729 §3.2.6 / §4.1.6, the 10 LSP values split into two groups of 5 (odd-indexed and even-indexed). Each group produces a 5th-order polynomial whose roots are on the unit circle at `±q_i`:

```
F1(z) = Π_{i=1,3,5,7,9} (1 − 2·q_i·z^-1 + z^-2)
F2(z) = Π_{i=2,4,6,8,10} (1 − 2·q_i·z^-1 + z^-2)
```

(Indexing convention: spec uses 1-based, Go uses 0-based. Follow spec indexing in comments, use 0-based in code.)

Each product expands via the recurrence:

```
f[n+1][k] = f[n][k] − 2·q · f[n][k-1] + f[n-1][k]      (indices into a growing polynomial)
```

where a separate state keeps one row back. After 5 expansion steps, `F1` and `F2` have coefficients `f1[0..5]` and `f2[0..5]`. Then:

```
A(z) = [(1 + z^-1)·F1(z) + (1 − z^-1)·F2(z)] / 2
```

Coefficient-wise:

```
a[0] = 1
a[1..5]  = (f1[1..5] + f1[0..4]  + f2[1..5] − f2[0..4]) / 2
a[6..10] = (f1[5..1] + f1[4..0]  − f2[5..1] + f2[4..0]) / 2   (mirrored)
```

More cleanly, compute all 11 terms via a symmetric loop — read §3.2.6 for the exact assembly.

**Q-format analysis:**

- q (LSP) is Q15 Word16.
- Intermediate polynomial coefficients f1, f2 can reach magnitudes up to ~16 on the unit circle, so they live in **Q28 Word32** (≈ full Q15 times 2^13 headroom).
- Final LP coefficients A[0..10] are **Q12 Word16** with `A[0] = 4096`.

The coefficient recurrence uses `LMac` with the −2·q multiplier; carry the `f_prev` row in Word32.

- [ ] **Step 3: Implement `lspToLP`**

Create `internal/lsp/lsp_lp.go`. Derivation of the recurrence from first principles (matches §3.2.6 — cross-check once implemented):

**F1 / F2 polynomial expansion.** Each factor `(1 − 2·q·z^-1 + z^-2)` is applied in turn. If `f_prev[j]` is the coefficient of `z^-j` before multiplication, then after multiplication:

```
f_new[j] = f_prev[j] − 2·q·f_prev[j−1] + f_prev[j−2]     (with f_prev[-1]=f_prev[-2]=0)
```

Starting from `f[0]=1` (all others 0), after 5 factors `F1` has degree 10 with 11 coefficients.

To compute the update in place, sweep `j` from high to low so `f_prev[j−1]` and `f_prev[j−2]` still hold their pre-update values when used.

**A(z) assembly.** Per §3.2.6:

```
A(z) = ((1 + z^-1)·F1(z) + (1 − z^-1)·F2(z)) / 2
```

Coefficient-wise (with `F1[-1] = F2[-1] = 0` outside the array):

```
a[k] = (F1[k] + F1[k−1] + F2[k] − F2[k−1]) / 2     for k ∈ [0, 10]
```

At `k=0`: `a[0] = (F1[0] + F2[0]) / 2 = (1 + 1)/2 = 1`. With Q28 representation of the 1.0 in F1/F2 (`1 << 28`) and Q12 target for A, the final right-shift is 17 bits (Q28 → Q12 after a `/2` is `>> 17`).

```go
package lsp

import "github.com/exedev/g729/internal/fixed"

// lspToLP converts a 10-element Q15 LSP vector into the 11
// coefficients of the synthesis filter A(z) in Q12 Word16, with
// a[0] = 4096 (i.e. 1.0 Q12). Per ITU-T G.729 §3.2.6 / §4.1.6:
//
//     F1(z) = Π_{i ∈ {0,2,4,6,8}} (1 − 2·q_i·z^-1 + z^-2)
//     F2(z) = Π_{i ∈ {1,3,5,7,9}} (1 − 2·q_i·z^-1 + z^-2)
//     A(z)  = ((1 + z^-1)·F1(z) + (1 − z^-1)·F2(z)) / 2
//
// F1 and F2 are accumulated in Q28 Word32 (Q15 LSPs × Q13 growth
// headroom) so that no polynomial coefficient saturates during the
// five factor multiplications. The final downscale to Q12 is a
// rounding right shift by 17.
func lspToLP(lsp *[10]int16, a *[11]int16) {
    var f1, f2 [11]fixed.Word32
    f1[0] = 1 << 28
    f2[0] = 1 << 28

    for step := 0; step < 5; step++ {
        q1 := lsp[2*step]   // LSP slots 0,2,4,6,8 → F1
        q2 := lsp[2*step+1] // LSP slots 1,3,5,7,9 → F2

        // The degree of each polynomial after `step` factors is
        // 2*step. Only coefficients f[0..2*(step+1)] will be touched.
        top := 2*step + 2
        for j := top; j >= 2; j-- {
            f1[j] = polyStep(f1[j], q1, f1[j-1], f1[j-2])
            f2[j] = polyStep(f2[j], q2, f2[j-1], f2[j-2])
        }
        // j == 1: f[j-2] term vanishes.
        f1[1] = polyStep(f1[1], q1, f1[0], 0)
        f2[1] = polyStep(f2[1], q2, f2[0], 0)
        // j == 0: f[j-1] and f[j-2] both vanish — no change.
    }

    // Assemble A(z). a[k] = (F1[k] + F1[k-1] + F2[k] - F2[k-1]) / 2
    // then right-shift from Q28 to Q12 (>>16) and from the /2 (>>1)
    // → net >>17, with rounding.
    //
    // Using int64 widening because we are combining two Q28 Word32
    // values; the additive worst case fits in int64 comfortably.
    for k := 0; k <= 10; k++ {
        var prev1, prev2 fixed.Word32
        if k > 0 {
            prev1 = f1[k-1]
            prev2 = f2[k-1]
        }
        sum := int64(f1[k]) + int64(prev1) + int64(f2[k]) - int64(prev2)
        // Rounding right shift by 17: add 2^16 then >>17.
        sum = (sum + (1 << 16)) >> 17
        if sum > 32767 {
            sum = 32767
        } else if sum < -32768 {
            sum = -32768
        }
        a[k] = int16(sum)
    }
}

// polyStep computes one coefficient update of the Chebyshev
// recurrence:
//
//     f_new = f − 2·q·f_prev1 + f_prev2
//
// q is Q15 Word16, f / f_prev1 / f_prev2 are Q28 Word32. The
// 2·q·f_prev1 product is formed in int64 to avoid overflow
// (|q|·|f_prev1| ≤ 2^15 · 2^31 ≈ 2^46, well inside int64) and then
// right-shifted by 15 to bring the product back into Q28. Result is
// clamped to Word32 range via fixed.LAdd / fixed.LSub composition so
// any accidental overflow saturates rather than wraps.
func polyStep(f fixed.Word32, q int16, fPrev1, fPrev2 fixed.Word32) fixed.Word32 {
    // 2·q·f_prev1 in Q(15+28+1) = Q44, then >>15 → Q29 → >>1 → Q28.
    prod := (int64(q) * int64(fPrev1)) >> 14 // 2·q·f_prev1 in Q28
    // Saturate prod to Word32 defensively.
    if prod > int64(fixed.Max32) {
        prod = int64(fixed.Max32)
    } else if prod < int64(fixed.Min32) {
        prod = int64(fixed.Min32)
    }
    result := fixed.LSub(f, fixed.Word32(prod))
    result = fixed.LAdd(result, fPrev2)
    return result
}
```

**Subtleties Copilot must resolve against the spec:**

1. **Shift count for the 2·q·f_prev1 product.** The derivation above says Q15 × Q28 → Q43, then `·2` → Q44, then `>>15` → Q29, then `>>1` → Q28 (net `>>14`). Verify by tracing units: `q` in Q15 means `q_real = q/2^15`; `f_prev1` in Q28 means `f_real = f_prev1/2^28`; their product as real numbers is `(q · f_prev1) / 2^43`; multiplied by 2 is `(q · f_prev1) / 2^42`; to represent in Q28 multiply by `2^28` giving `(q · f_prev1) / 2^14`. So `>>14` is correct.

2. **Rounding shift at A-assembly.** `(1 << 16)` bias before `>> 17` is standard mid-point rounding for signed right shifts. If the spec prescribes truncation, remove the bias.

3. **Tests in Step 1 catch these two subtleties only weakly.** The `a[0] = 4096` test in particular is insensitive to any positive scaling error because the leading coefficient of F1 and F2 both come from the `1 << 28` initial value, not from any LSP multiplication. Task 13's integration test (decoding real indices) is the real check.

If `TestLSPToLPAllZeroLSPProducesSymmetric` fails, the culprit is almost certainly the odd/even split: with all LSPs zero, each factor is `(1 + z^-2)`, so F1 and F2 are identical, and A(z) must equal F1 (only even terms). Any deviation means the split or the assembly is wrong.

```go
    pastResiduals [4][10]int16
    prevLSP       [10]int16 // Q15, previous frame's post-stability LSP
    initialized   bool
}

func (d *Decoder) Reset() {
    *d = Decoder{}
}

func (d *Decoder) Decode(idx Indices) (sf1, sf2 [11]int16) {
    // 1. Split-VQ combine.
    var residual [10]int16
    combineResidual(idx.L1, idx.L2, idx.L3, &residual)

    // 2. MA predictor reconstruction.
    var lsf [10]int16
    d.applyPredictor(idx.L0, &residual, &lsf)

    // 3. Stability enforcement.
    enforceLSFStability(&lsf)

    // 4. LSF → LSP per-dimension.
    var lsp [10]int16
    for i := 0; i < 10; i++ {
        lsp[i] = lsfToLSP(lsf[i])
    }

    // 5. First-frame handling: before we have a real prevLSP, use the
    // current one so sf1 == sf2 == LSP(current). The ITU spec §4.1.2
    // covers this as the decoder's Reset-recovery convention; confirm
    // against the spec text.
    if !d.initialized {
        d.prevLSP = lsp
        d.initialized = true
    }

    // 6. Per-subframe LSP interpolation.
    var lspSF1, lspSF2 [10]int16
    interpolateLSP(&d.prevLSP, &lsp, &lspSF1, &lspSF2)

    // 7. LSP → LP per subframe.
    lspToLP(&lspSF1, &sf1)
    lspToLP(&lspSF2, &sf2)

    // 8. Update interpolation state.
    d.prevLSP = lsp

    return sf1, sf2
}
```

```go
// Package lsp implements the G.729 + Annex A decoder's line-spectral
// pair reconstruction. It consumes the 18 LSP bits of one frame
// (L0 / L1 / L2 / L3) and produces two 11-coefficient LP filter
// vectors — one per subframe — that the synthesis filter in
// internal/synth consumes directly.
//
// # Pipeline
//
// Per ITU-T G.729 §3.2.4, §3.2.5, §3.2.6 and §4.1.1–§4.1.2:
//
//  1. Split-VQ combine:   L1, L2, L3 indices → 10-element Q13 residual.
//  2. MA prediction:       r̂(n) + order-4 MA state → quantized Q13 LSF.
//  3. Stability:           enforce monotonic order and minimum spacing.
//  4. LSF → LSP:           cos lookup via tables.CosLSP, Q15 output.
//  5. Interpolation:       half-and-half with prev frame for subframe 1,
//                          current frame directly for subframe 2.
//  6. LSP → LP:            Chebyshev polynomial expansion per subframe,
//                          producing a[0..10] Q12 with a[0] = 4096.
//
// Step 2 carries state across frames (past 4 residuals); step 5 carries
// one frame of LSP history. A Decoder's zero value is a valid Reset
// state.
//
// # Numerical contract
//
//   Indices: raw integers from the bitstream — L0 ∈ {0,1},
//            L1 ∈ [0,127], L2, L3 ∈ [0,31].
//   LSF values: Q13 Word16, 0 ≤ ω < π (Q13 full-scale π = 25736).
//   LSP values: Q15 Word16, −1 < q ≤ 1.
//   LP output:  Q12 Word16, a[0] = 4096, a[i] bounded by LPC stability.
//
// # Scratch-from-spec
//
// Every codebook, predictor coefficient, and cosine table value comes
// from the ITU-T G.729 specification document. No reference C, no
// bcg729, no other implementation was consulted. Every arithmetic step
// routes through internal/fixed so that ITU's saturation semantics
// are preserved.
//
// # Concurrency
//
// Decoder is not safe for concurrent use. One instance per decoder
// channel.
package lsp
```
