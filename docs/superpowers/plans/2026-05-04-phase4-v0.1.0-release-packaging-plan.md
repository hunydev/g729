## §1. Disposition entry

Phase 4 is a **release-packaging cycle**, not a code-correctness cycle.
The goal is publishing the codec as MIT open source under tag
`v0.1.0-rc1`, with deployment-target documentation (MRCP/TTS RTP),
honest known-limitations disclosure, and zero new G.729 algorithm
work.

**Hard scope boundaries (binding):**
- NO Phase 3c entry (no enumerable spec-defined candidate remains under I1).
- NO H-CENTER re-entry.
- NO decoder production code modification.
- NO new external G.729 implementation source consultation.
- NO claim of ITU byte-exact conformance, ITU certification, or
  Annex B / Annex G / G.729.1 support.

**Acceptance scope (binding):**
- G.729A-compatible 8 kbps RTP-suitable encoder/decoder
- 10 ms frame: 80 int16 samples ↔ 10 packed bytes
- `ptime=10`, `ptime=20`
- `annexb=no`
- Single-stream Encoder / Decoder (concurrent calls on same instance = data race; documented)
- `EncodeFrame` / `DecodeFrame` zero-allocation steady-state
- Streaming `Encoder.Write` / `Encoder.Flush`

## §5. SDP / RTP examples (for README + release note)

`ptime=10`, single G.729 frame per RTP packet:

```
m=audio 49170 RTP/AVP 18
a=rtpmap:18 G729/8000
a=fmtp:18 annexb=no
a=ptime:10
a=maxptime:10
```

`ptime=20`, two G.729 frames bundled per RTP packet (20 bytes payload):

```
m=audio 49170 RTP/AVP 18
a=rtpmap:18 G729/8000
a=fmtp:18 annexb=no
a=ptime:20
a=maxptime:20
```

Notes (for README narrative):
- Payload type 18 is statically assigned by IANA for `G729/8000`.
- `annexb=no` MUST be advertised because this codec does not
  implement Annex B SID/CNG/DTX. Receiving SID frames is undefined
  behaviour in v0.1.0.
- For `ptime=20`, the sender concatenates two consecutive 10-byte
  encoder outputs into a single 20-byte RTP payload; receiver
  feeds them to two consecutive `DecodeFrame` calls.
