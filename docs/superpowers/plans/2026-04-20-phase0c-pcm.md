# Phase 0c — internal/pcm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Implement the `internal/pcm` package — the encoder-side pre-processing (combined 1/2 input scaling + 140 Hz high-pass filter) and the decoder-side output scaling (multiply by 2 with saturation to `int16`). This isolates all the int16 ↔ internal-scale conversions in one place so later blocks (LPC analysis, synthesis, post-filter) can assume a consistent numerical contract.

**Architecture:** One `PreProcessor` struct with a per-channel biquad-style filter memory, exposing `Reset` and `Process(in []int16, out []int16)`. A free function `ScaleUpSat(in []int16, out []int16)` for the decoder post-scaling. Both hot-path entry points are zero-allocation: filter memory lives in the caller-owned `PreProcessor` value, slices are caller-owned, and all arithmetic goes through `internal/fixed` primitives.

**Tech Stack:** Go 1.22+. Depends on `internal/fixed` for saturating arithmetic primitives (`LMac`, `LMsu`, `LAdd`, `LSub`, `Round`, `Shl`, `Shr`, etc.). No standard-library DSP; no third-party dependencies. Scratch-from-spec — coefficient values and filter topology taken from ITU-T G.729 + Annex A (§3.1.1 "Pre-processing" and §4.2 / §5.3.1 for the output scaling), never from reference C or any other implementation.

## Context for the implementing engineer

### What the package exists for

Every other block in the codec assumes its input is "pre-processed". That means:

- Any DC offset or sub-140 Hz rumble in the input has been removed (so the LPC analysis sees a flat low-frequency response and the long-term predictor is not chasing a slow drift).
- The input amplitude has been halved (the filter gain of 1/2 is baked in), so intermediate values in the LPC / pitch / ACELP search don't overflow the 16-bit fixed-point arithmetic under loud inputs.

On the decoder side, the synthesizer and post-filter work in that same halved-amplitude domain. The final step is to scale the output back up by 2, saturating to the `int16` range where the doubling overflows. That's the symmetric counterpart of the encoder's scaling.

No frequency-domain filtering is performed on the decoder side in this package — ITU-T G.729 §4.2 places the long-term post-filter, short-term post-filter, tilt compensation, and adaptive gain control in the decoder post-filter, and those are out of scope here. Any decoder-side high-pass filtering (the 100 Hz post-filter described in §4.2.5 of the full G.729 spec) will live in the post-filter package in a later phase, not here.

### ITU-T G.729 §3.1.1 — encoder pre-processing

The spec text of the pre-processing transfer function:

```
                  0.46363718 − 0.92724705·z^-1 + 0.46363718·z^-2
    H_h1(z) = ─────────────────────────────────────────────────────
                    1 − 1.9059465·z^-1 + 0.9114024·z^-2
```

This is a second-order pole-zero high-pass filter with cutoff ≈140 Hz at the 8 kHz sampling rate. The spec also says the `1/2` input scaling is folded into the numerator coefficients (i.e. the transfer function above already includes the `×1/2`). That gives the direct-form-I recursion:

```
    y[n] = 1.9059465·y[n−1] − 0.9114024·y[n−2]
           + 0.46363718·x[n]
           − 0.92724705·x[n−1]
           + 0.46363718·x[n−2]
```

Here `x[n]` is the raw `int16` input sample (treated as `Q0`) and `y[n]` is the pre-processed output (conceptually still `int16`-range but with the filter's 6 dB attenuation applied).

**Numerical contract (this is what later blocks depend on):**
- `in[i]` is int16 (Q0), typically filled from 16-bit little-endian PCM.
- `out[i]` is int16, fits in the same range, and is what the LPC analysis window consumes.
- The filter is causal and stateful. Two previous input samples and two previous output values must persist across calls so that a 10 ms frame (80 samples) fed one frame at a time produces the same output as feeding all samples in one call.

**Coefficient quantization:** The real-valued coefficients above are irrational with respect to any power-of-two Q-format, so they must be rounded. A conventional choice in ITU fixed-point code is:

- `a1 = 1.9059465` and `a2 = −0.9114024` fit in Q12 (they have magnitude < 2, so Q12 fits in Word16 with headroom): `a1_q12 = round(1.9059465 · 4096) = 7807`, `a2_q12 = round(−0.9114024 · 4096) = −3733`. **Or** in Q13, which doubles the precision but still fits for `|a| < 2`: `a1_q13 = round(1.9059465 · 8192) = 15614`, `a2_q13 = round(−0.9114024 · 8192) = −7465`.
- `b0 = b2 = 0.46363718` and `b1 = −0.92724705` are all less than `1.0` in magnitude, so Q13 comfortably fits: `b0_q13 = round(0.46363718 · 8192) = 3798`, `b1_q13 = round(−0.92724705 · 8192) = −7597`.

**You may choose a different Q-format** as long as (1) no coefficient saturates its chosen representation, (2) the quantization error per coefficient is less than 1 ULP of the chosen format, and (3) the test in Task 2 passes. Document the chosen format in a comment near the constants so later readers can reconstruct what the integers mean.

**State precision:** Storing `y[n-1]` and `y[n-2]` as plain `int16` (Q0) works but throws away feedback precision on each step and can color the frequency response audibly. A standard fixed-point biquad keeps the *accumulator-domain* state — the `Word32` pre-rounding sum — so that rounding error is not accumulated. You may implement either way; the impulse-response test in Task 5 will reveal whether you have unacceptable error.

### ITU-T G.729 §4.2 — decoder output scaling

The decoder runs its synthesis and post-filter entirely in the halved-amplitude domain. The final step restores the original amplitude by multiplying each output sample by 2. Because the synthesizer is allowed to produce values up to the full `int16` range already (the /2 amplitude headroom is not guaranteed to be preserved through the ACELP gain application), the ×2 scaling must saturate, clipping to `±32767` where it would otherwise overflow.

**Numerical contract:**
- `in[i]` is int16, the post-filtered synthesized sample.
- `out[i]` is int16, `saturate_int16(2·in[i])`. Overflow clamps to `±Max16`.

### Dependency contract

- `internal/pcm` imports `internal/fixed` only. No other internal packages.
- Every fixed-point arithmetic operation routes through `internal/fixed` primitives (`LMac`, `LMsu`, `LAdd`, `LSub`, `LMult`, `Round`, `Shl`, `Shr`, `Mult`, `MultR`, `Saturate`, `Add`, `Sub`). Go's built-in `+`, `-`, `*` on `int16` / `int32` **must not** be used for codec arithmetic because they wrap on overflow; this rule is enforced by example, not by vet, so read every arithmetic line twice.
- No allocation in `PreProcessor.Process` or `ScaleUpSat`. Filter memory is part of the `PreProcessor` value; output slices are caller-owned.

### Frame length convention

One G.729 frame is 80 samples (10 ms at 8 kHz). The pre-processor does not itself require a specific frame boundary — you can feed any length slice — but benchmarks and allocation tests use `FrameLength = 80` as the canonical chunk size to match how the encoder will call it.

```go
package pcm

// FrameLength is the number of PCM samples in one G.729 frame
// (10 ms at 8 kHz).
const FrameLength = 80

// PreProcessor applies the ITU-T G.729 §3.1.1 input pre-processing:
// a second-order pole-zero high-pass filter at ~140 Hz with the 1/2
// input scaling folded into the numerator coefficients.
//
// Filter memory is kept across calls so that a 10 ms frame fed one
// frame at a time produces the same output as feeding the whole signal
// in one call. The zero value is usable and equivalent to calling
// Reset on a fresh instance.
//
// PreProcessor is not safe for concurrent use. Each channel of a
// multi-channel encoder should own a dedicated PreProcessor.
type PreProcessor struct {
	// State fields are filled in by Task 3. They are intentionally
	// unnamed here so the skeleton compiles without prejudging the
	// Q-format of the state.
	//
	// TODO(phase0c-task3): add x1, x2, y1, y2 fields in the chosen
	// Q-format.
	_unused byte
}

// Reset returns the filter to its initial state (all memory zero). A
// PreProcessor should be Reset before the first call when an instance
// is being reused across independent streams.
func (p *PreProcessor) Reset() {
	*p = PreProcessor{}
}

// Process applies the pre-processing filter to in, writing the result
// to out. in and out must have the same length and may alias. Process
// allocates nothing.
//
// At the skeleton stage, Process just zeros out.
func (p *PreProcessor) Process(in, out []int16) {
	n := len(in)
	if len(out) < n {
		n = len(out)
	}
	for i := 0; i < n; i++ {
		out[i] = 0
	}
}
```

The `_unused byte` field is a placeholder so the struct compiles before Task 3 defines the real state. It will be replaced.

```go
import (

// TestCoefficientValues asserts that the integer Q-format coefficients
// defined in coeffs.go, when converted back to real numbers, agree
// with the ITU-T G.729 §3.1.1 filter specification within one unit of
// least precision (ULP) of the chosen Q-format.
func TestCoefficientValues(t *testing.T) {
	cases := []struct {
		name    string
		got     int16
		want    float64
		qFormat uint // e.g. 12 for Q12, 13 for Q13
	}{
		{"A1", A1, 1.9059465, A1Q},
		{"A2", A2, -0.9114024, A2Q},
		{"B0", B0, 0.46363718, BQ},
		{"B1", B1, -0.92724705, BQ},
		{"B2", B2, 0.46363718, BQ},
	}
	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			scale := float64(int64(1) << tc.qFormat)
			actual := float64(tc.got) / scale
			// One ULP in the chosen Q-format:
			tol := 1.0 / scale
			if math.Abs(actual-tc.want) > tol {
				t.Errorf("%s = %d (Q%d, ≈ %.8f), want %.8f ± %.8f",
					tc.name, tc.got, tc.qFormat, actual, tc.want, tol)
			}
		})
	}
}
```

```go
package pcm

// High-pass pre-processing filter coefficients from ITU-T G.729 §3.1.1:
//
//     H_h1(z) = (0.46363718 − 0.92724705·z^-1 + 0.46363718·z^-2)
//               / (1 − 1.9059465·z^-1 + 0.9114024·z^-2)
//
// The 1/2 input scaling mandated by the spec is already folded into
// the numerator coefficients above (this is the reason the dc gain of
// the numerator at z=1 is 0, with peak |b1| = 2·|b0|).
//
// Denominator coefficients (a1, a2) have magnitudes less than 2, so
// Q13 fits with headroom: scaling by 2^13 = 8192 keeps the rounded
// values inside ±Max16.
//
// Numerator coefficients (b0, b1, b2) have magnitudes less than 1, so
// Q13 also fits and matches the denominator precision.
//
// If you change these Q-formats, update coeffs_test.go's expected ULP.
const (
	A1Q = 13 // Q-format exponent for A1
	A2Q = 13 // Q-format exponent for A2
	BQ  = 13 // Q-format exponent for B0, B1, B2
)

// Integer Q-format coefficients. Values are round(real·2^Q):
//
//   A1 = round( 1.9059465 · 2^13) = round(15615.19...) = 15615
//   A2 = round(-0.9114024 · 2^13) = round(-7464.92...) = -7465
//   B0 = round( 0.46363718 · 2^13) = round(3798.40...) =  3798
//   B1 = round(-0.92724705 · 2^13) = round(-7596.03...) = -7596
//   B2 = round( 0.46363718 · 2^13) = round(3798.40...) =  3798
//
// Double-check by hand before committing: the spec coefficients are
// irrational and any transcription error here becomes a permanent
// 6 dB–per-LSB audio artifact later.
const (
	A1 int16 = 15615
	A2 int16 = -7465

	B0 int16 = 3798
	B1 int16 = -7596
	B2 int16 = 3798
)
```

```go
func TestPreProcessor_RejectsDC(t *testing.T) {
	// A high-pass filter must reject DC: feed a long constant signal
	// and the output must converge to zero. Use a moderately long
	// input (many times the filter's settling time) and check that
	// the last handful of output samples are within a small band of
	// zero.
	var p PreProcessor
	const (
		n  = 1024
		dc = int16(2000)
	)
	in := make([]int16, n)
	out := make([]int16, n)
	for i := range in {
		in[i] = dc
	}
	p.Process(in, out)

	// The tail must be small compared to the input. A well-implemented
	// biquad at 140 Hz settles well within 256 samples at 8 kHz, so by
	// sample 512 the DC component should be below 1 LSB times a small
	// multiplier.
	const tailTol = 4
	for i := n - 16; i < n; i++ {
		if out[i] > tailTol || out[i] < -tailTol {
			t.Fatalf("DC not rejected: out[%d] = %d (tol ±%d)", i, out[i], tailTol)
		}
	}
}
```

```go
// Process applies the pre-processing filter to in, writing the result
// to out. len(out) must be >= len(in); any extra tail in out is
// untouched. in and out may alias. Process allocates nothing.
func (p *PreProcessor) Process(in, out []int16) {
	n := len(in)
	if len(out) < n {
		n = len(out)
	}

	// Recursion (real-valued, from spec):
	//   y[n] = a1·y[n-1] + a2·y[n-2] + b0·x[n] + b1·x[n-1] + b2·x[n-2]
	//
	// Q-format analysis:
	//   - Coefficients (A1, A2, B0, B1, B2) are Q13 Word16.
	//   - State (x1, x2, y1, y2) is Q0 Word16, widened to int32 only
	//     for uniform field typing.
	//   - fixed.LMac(acc, a, b) computes Saturate(acc + 2·a·b), so
	//     one LMac of a Q13 coefficient and a Q0 value contributes a
	//     Q(13+0+1) = Q14 term.
	//   - After all five LMacs, acc represents the real-valued
	//     result scaled by 2^14 (Q14 Word32).
	//
	// To convert Q14 Word32 to Q0 Word16 with rounding and saturation
	// we need an arithmetic right shift by 14 with rounding. Using
	// the available primitives that is:
	//
	//     Round(LShl(acc, 2))
	//
	// because LShl(acc, 2) multiplies by 4 (Q14 → Q16) with
	// saturation, and Round(x) = ExtractH(x + 0x8000) which is a
	// right shift by 16 with rounding. Net effect: right shift by
	// 14 with rounding, saturation preserved at both steps.
	//
	// LShl may saturate at ±Max32 for outputs that would exceed the
	// int16 range; Round of a saturated Max32 yields Max16 (or Min16
	// for negative saturation), which is the correct clipping
	// behavior.

	for i := 0; i < n; i++ {
		x0 := in[i]

		// Numerator contributions.
		var acc fixed.Word32
		acc = fixed.LMac(acc, B0, x0)
		acc = fixed.LMac(acc, B1, int16(p.x1))
		acc = fixed.LMac(acc, B2, int16(p.x2))

		// Feedback: A1, A2 are the positive-form coefficients of the
		// transfer function denominator (see coeffs.go and §3.1.1).
		acc = fixed.LMac(acc, A1, int16(p.y1))
		acc = fixed.LMac(acc, A2, int16(p.y2))

		// Q14 Word32 → Q0 Word16 with rounding and saturation.
		y0 := fixed.Round(fixed.LShl(acc, 2))

		out[i] = y0

		// Shift state. The order matters: read the "2 steps ago"
		// slot from the "1 step ago" slot first, then overwrite the
		// "1 step ago" slot with the current step.
		p.x2 = p.x1
		p.x1 = int32(x0)
		p.y2 = p.y1
		p.y1 = int32(y0)
	}
}
```

Important implementation notes (read before hitting Save):

1. The comment block above is load-bearing for understanding — do not delete it. The Q-format math is the place a careful reader will check when bit-errors are later found in integration.
2. `fixed.LMac(acc, a, b)` is defined as `Saturate(acc + 2·a·b)` in ITU-T G.191 semantics (see `internal/fixed/mult.go`). The factor of 2 changes the Q arithmetic by one LSB as noted.
3. `fixed.LShl(acc, 1)` followed by `fixed.Round` normalizes to int16 with rounding. An alternative is `fixed.Round(fixed.LShl(acc, 2))` if you prefer to think in Q16 before rounding — both produce the same output up to one-LSB rounding, which the tolerance-based tests accommodate.
4. If `fixed.LShl(acc, 1)` saturates (acc is already at ±Max32/2), the output will be Max16 / Min16. This is the correct behavior under ITU saturation.
5. `in[i]` aliasing `out[i]` is safe: we read `x0 := in[i]` first, then overwrite `out[i]` later. The state updates use the local `x0` and `y0`, not re-reads of `in`/`out`.

```go
package pcm

import "github.com/hunydev/g729/internal/fixed"

// ScaleUpSat multiplies each sample in `in` by 2 with int16 saturation
// and writes the result to `out`. This is the decoder-side inverse of
// the 1/2 amplitude scaling applied in PreProcessor: the decoder
// synthesizes samples in the halved-amplitude domain, and this final
// step restores the original amplitude, clipping to ±Max16 where the
// doubling would overflow.
//
// in and out may alias (in-place is safe). Processes
// min(len(in), len(out)) samples. Allocates nothing.
//
// See ITU-T G.729 §4.2 for the decoder output-scaling requirement.
func ScaleUpSat(in, out []int16) {
	n := len(in)
	if len(out) < n {
		n = len(out)
	}
	for i := 0; i < n; i++ {
		out[i] = fixed.Shl(in[i], 1)
	}
}
```

`fixed.Shl(x, 1)` is defined as `Saturate(x << 1)` — exactly the ×2-with-saturation semantics the spec asks for.

## Notes on bit-exactness vs. this plan

This plan produces a working, mathematically correct, algebraically verified pre-processor and output-scaler, but it does not prove bit-exact agreement with the ITU reference implementation. That proof requires ITU test vectors (`algthm.in` → isolated pre-processor output) which are not fed through standalone in the ITU STL package — they appear only as part of encoder-integrated vectors.

Bit-exact verification for the pre-processor will happen implicitly during Phase 2 (encoder integration) when the end-to-end encoder output is compared against ITU vectors. If pre-processor coefficients or state handling are off, the encoder-level bit-exact test will fail and trace back here. The impulse-response tolerance test in Task 5 (`TestPreProcessor_ImpulseMatchesReference`) is the strongest standalone quantitative check available at this phase.

If Phase 2 reveals a bit-exact mismatch traceable to this package, the most likely adjustments (in rough order of likelihood) are:
1. Coefficient Q-format change from Q13 to something the ITU implementation uses (e.g. Q12 for `a1`, `a2` and Q15 for `b0`, `b1`, `b2`; these are also common ITU conventions and change only the `*Q` exponent constants, the integer values, and the `LShl` count in the output rescale).
2. Rounding convention change — the output rescale `fixed.Round(fixed.LShl(acc, 2))` currently uses banker-style rounding via `Round`. A floor-style rescale (`fixed.ExtractH(fixed.LShl(acc, 2))`) differs by one LSB on half-tie samples.
3. Feedback precision — keeping both the current Word16 Q0 output and a Word32 "error accumulator" for the residual part of the rescale, fed back in the next step, is a known technique for higher-precision biquads. Requires rethinking the state layout but is localized to `Process`.

None of those adjustments affect the public API or callers.
