# v0.1.0-rc1 — clean-room MIT pure-Go G.729A-compatible codec

Date: 2026-05-08 (release candidate)
Module: `github.com/hunydev/g729`
Branch / release tag: `main` / `v0.1.0-rc1`

---

## Highlights

First public release candidate of `github.com/hunydev/g729`, a
pure-Go G.729A-compatible 8 kbps speech codec implemented under a
strict clean-room constraint and licensed under the MIT License.

Intended deployment target: server-side audio egress for MRCP /
TTS / IVR systems on RTP payload type 18 (`G729/8000`). The outbound
encoder send path now passes the FFmpeg black-box product gate for
`G729/8000 annexb=no` speech frames.

This release ships with a bounded production claim: the outbound
encoder/RTP send path passes the FFmpeg executable black-box product
gate for `G729/8000 annexb=no` speech frames, and the strict local
decoder passes FFmpeg black-box regression gates for the local encoder
payload plus a local, non-redistributed Asterisk-origin payload sample. It does not
claim ITU byte-exact conformance, ITU certification, or exhaustive
qualification of arbitrary external G.729 payloads. Full disposition in the
[Phase 3-final closure report](../superpowers/plans/2026-05-04-phase3-final-closure-report.md)
and the rc1 verification log.

## Out of scope

The following are explicitly **not** part of v0.1.0:

- ITU reference byte-exact conformance
- ITU vector full byte-EQ
- ITU certified conformance claim
- G.729 Annex B (SID / CNG / DTX)
- G.729.1 (wideband / scalable)
- G.729D / G.729E
- Built-in RTP packetization library
- DTMF / RFC 2833 telephone-event handling

## Known limitations

See README §"Known limitations" and Phase 3-final closure report §7.
The release introduces no new binding failures relative to that
closure, and the conformance expected-failure inventory is now empty.

The project ships three test layers:

* **Default suite (binding)** — `go test ./...` PASS at the RC tag.
* **Conformance suite (informational)** — `go test -tags=conformance ./...`
  contains 0 expected failures; encoder byte-EQ vectors are retained as
  source-divergence diagnostics.
* **Diagnostic suite (informational)** — `go test -tags=diagnostic ./...`
  contains 5 PSTdomain known-difference pins (Phase 1o D-3).
  `TestDiagnostic_SinglePulseChain` remains as a PASSing
  instrumentation log.

Substantive limitations and informational diagnostics carried into the
RC:

1. **Outbound encoder FFmpeg black-box gate PASS.** On the ITU SPEECH
   corpus, `SPEECH.BIT -> ffmpeg` measures `GlobalSNR=7.04 dB`,
   `SegSNR=4.39 dB`; `SPEECH.IN -> our encoder -> ffmpeg` measures
   `GlobalSNR=5.09 dB`, `SegSNR=3.05 dB`, within the required 2 dB
   delta on both metrics.
2. **Local roundtrip decoder quality gate PASS.** On the local encoder's
   own SPEECH payload, the strict local decoder tracks FFmpeg at about
   `GlobalSNR=13.78 dB`, `SegSNR=13.99 dB`, and RMS ratio `0.991`
   local-vs-FFmpeg. End-to-end source quality remains bounded by the
   outbound encoder gate, not by ITU byte-exact certification.
3. **Local Asterisk-origin payload decoder gate PASS.** The strict
   local decoder tracks FFmpeg on a local non-redistributed Asterisk
   payload sample at about `GlobalSNR=14.64 dB`, `SegSNR=15.23 dB`,
   `corr=0.983`, and RMS ratio `0.985`. This is a useful inbound
   regression gate for MRCP/SIP integration, but not blanket certification
   for arbitrary external G.729 senders. The experimental enhanced
   listening path is non-strict and is not conformance evidence.
4. 0 root-package encoder byte-EQ expected failures. LSP vector, TAME
   byte-EQ, former Phase 2c closed-loop pitch, and Phase 2d FCB pins
   now pass as source-divergence diagnostics after clean-room numeric
   handoff audits.
5. 5 `internal/decoder` PSTdomain PASS-by-design pins (Phase 1o D-3),
   relocated to the diagnostic suite.
6. `TestDiagnostic_SinglePulseChain` diagnostic-only log, relocated
   to the diagnostic suite and currently PASSing.

CI verification asserts that no failure appears in the default
suite, and that the conformance/diagnostic suites match the
documented inventories above.

## Clean-room declaration

This project maintains a clean-room constraint. No ITU reference C,
bcg729, FFmpeg, Sipro, or other G.729 implementation source was used.
Public specifications, test vectors, and independently written tests
were used. v0.1.0 does not claim ITU byte-exact conformance.

The clean-room I1 constraint was maintained continuously across all
phases (Phase 0 through Phase 4) of this codec's development. Each
phase plan, diagnostic appendix, and design note carries its own per-
document I1 declaration with full citation list.
