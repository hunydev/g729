## Highlights

First public release candidate of `github.com/exedev/g729`, a
pure-Go G.729A-compatible 8 kbps speech codec implemented under a
strict clean-room constraint and licensed under the MIT License.

Intended deployment target: server-side audio egress for MRCP /
TTS / IVR systems on RTP payload type 18 (`G729/8000`).

This release ships the codec under a **spec-compliance binding
criterion**: the decoder is verified spec-correct against ITU-T
G.729 (06/2012) + Annex A across seven independent diagnostic
axes, but does not claim ITU byte-exact conformance against the
ITU `SPEECH.PST` reference. Full disposition in the
[Phase 3-final closure report](../superpowers/plans/2026-05-04-phase3-final-closure-report.md).

## Out of scope

The following are explicitly **not** part of v0.1.0:

- ITU reference byte-exact conformance
- ITU vector full byte-EQ
- ITU certified conformance claim
- G.729 Annex B (SID / CNG / DTX)
- G.729.1 (wideband / scalable)
- G.729D / G.729E
- Built-in RTP packetization library
- DTMF / RFC 2833 telephone-event handling

## Known limitations

See README §"Known limitations" and Phase 3-final closure report §7.
Brief summary of the **9 documented failing tests** carried into this
RC (no new regressions; identical inventory pre/post Phase 3):

1. **Pipeline B SegSNR ≈ −0.90 dB** vs `SPEECH.PST`. Decoder
   spec-correct on 7 axes; reference vector divergence is structural
   under the clean-room constraint.
2. 4 root-package encoder byte-EQ FAIL-DEFERRED pins (Phase 2c / 2d / 2f).
3. 4 `internal/decoder` PSTdomain PASS-by-design pins (Phase 1o D-3).
4. 1 `TestDiagnostic_SinglePulseChain` diagnostic-only log.
5. `internal/gain/legacy_gcq12.go` test-only adapter retained;
   non-blocking housekeeping.

CI verification asserts that no failure outside this documented
inventory appears.

## Clean-room declaration

This project maintains a clean-room constraint. No ITU reference C,
bcg729, FFmpeg, Sipro, or other G.729 implementation source was used.
Public specifications, test vectors, and independently written tests
were used. v0.1.0 does not claim ITU byte-exact conformance.

The clean-room I1 constraint was maintained continuously across all
phases (Phase 0 through Phase 4) of this codec's development. Each
phase plan, diagnostic appendix, and design note carries its own per-
document I1 declaration with full citation list.

## Roadmap (informational; non-binding)

Post-v0.1.0 candidates, in no particular order:

- Phase 4-cleanup — remove `internal/gain/legacy_gcq12.go` test-only
  adapter once test consumers are migrated.
- Phase 4 conformance backlog — investigate the 4 encoder Phase 2c /
  2d / 2f byte-EQ FAIL-DEFERRED pins under continued I1 constraint.
- Phase 1o D-3 sample-40-41 PSTdomain drift — document as a
  permanent known limitation or open a dedicated diagnostic cycle if
  new spec-derived candidates emerge.
- v0.1.x patch releases for documentation / tooling fixes.
- v0.2.0 candidate work: pure decoder optimization, additional
  example programs, optional RTP packetization helper sub-module.

**Out of any v0.1.x roadmap:** Annex B (SID / CNG / DTX), G.729.1
wideband, G.729D / G.729E, ITU certification claim. Adding any of
these would require a new dedicated phase cycle and is not planned.
