### §8.C. ACELP C/S bitfield correction and remaining quality gap — 2026-05-07

§3.8.2 eq. (61) and eq. (62):

### §8.CA. P1 upper fractional edge normalization — 2026-05-08

### §8.CI. Decoder gain predictor width fix and encoder split — 2026-05-08

A gain-predictor width audit found the strict decoder's fixed-codebook gain
reconstruction was collapsing high-energy frames through an intermediate
Word16 prediction. The strict receiver-side gain path now keeps
`PredictedLogGain` wide through the log-gain subtraction and pow2
reconstruction. This is an implementation bug fix, not an audio-normalization
or listening-only correction.

The first production attempt applied the wider predictor to the encoder's
gain search and local synthesis commit as well. That broke the outbound
FFmpeg black-box encoder gate (`our encoder -> ffmpeg` fell to about
`GlobalSNR=1.69`, `SegSNR=1.09`). The encoder path is therefore explicitly
split: receiver-side reconstruction uses the wider predictor, while
encoder-side `PredictedGcQ12` and `Reconstruct` keep the legacy bounded
search/commit predictor surface.
